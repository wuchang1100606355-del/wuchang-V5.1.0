# 每小時系統部署檢查說明

## 概述

此系統會自動每小時檢查 `wuchang.life` 網域的部署狀態，確認首頁和登入頁是否可訪問，並聯繫 UI 電腦進行回報。

## 功能

1. **DNS 解析檢查**：確認 `wuchang.life` 網域可以正常解析
2. **首頁可訪問性檢查**：檢查 `https://wuchang.life/` 是否可訪問
3. **登入頁可訪問性檢查**：檢查 `https://wuchang.life/web/login` 是否可訪問
4. **UI 設備通知**：自動聯繫以下 UI 電腦進行回報：
   - LUNGsMSI (192.168.50.84)
   - POS-PC (192.168.50.88)
   - 本機 (192.168.50.249)

## 安裝與設置

### 1. 確保依賴已安裝

```bash
pip install requests urllib3
```

### 2. 設置定時任務（Windows）

#### 方法 A：使用 PowerShell 腳本（推薦）

```powershell
# 以管理員權限打開 PowerShell
cd "C:\wuchang V5.1.0\scripts"
.\setup_hourly_check_task.ps1
```

腳本會自動：
- 檢查 Python 環境
- 創建每小時執行一次的定時任務
- 設置任務在系統啟動後首次延遲 60 分鐘執行

#### 方法 B：手動創建定時任務

1. 打開「工作排程器」（Task Scheduler）
2. 點擊「建立基本工作」
3. 名稱：`WuchangHourlyDeploymentCheck`
4. 觸發程序：每日
5. 開始時間：選擇當前時間
6. 重複工作：每 1 小時
7. 動作：啟動程式
8. 程式或指令碼：`python`
9. 新增引數：`"C:\wuchang V5.1.0\scripts\hourly_deployment_check.py"`
10. 開始於：`C:\wuchang V5.1.0`

### 3. 測試執行

```bash
# 直接執行檢查腳本
python scripts/hourly_deployment_check.py

# 或使用批處理腳本
scripts\run_hourly_check.bat
```

## 檢查內容

### DNS 檢查

- 檢查 `wuchang.life` 是否可以解析為 IP 地址

### URL 檢查

系統會檢查以下 URL：

1. **首頁**：
   - `https://wuchang.life/`
   - `http://wuchang.life/`（如果 HTTPS 失敗）

2. **登入頁**：
   - `https://wuchang.life/web/login`
   - `http://wuchang.life/web/login`（如果 HTTPS 失敗）

每個 URL 檢查包括：
- HTTP 狀態碼
- 響應時間
- 內容長度
- 最終重定向 URL（如果有）
- 錯誤信息（如果無法訪問）

## 通知方式

### 1. HTTP 通知

如果 UI 設備運行 Web 服務（端口 80 或 8080），系統會嘗試通過 HTTP POST 發送通知。

### 2. 通知文件

系統會在 `notifications/` 目錄下創建 JSON 格式的通知文件，文件名格式：
```
deployment_check_{IP地址}_{時間戳}.json
```

UI 設備可以：
- 通過共享目錄讀取通知文件
- 通過文件同步服務同步文件

## 報告與日誌

### 檢查報告

每次檢查後會在 `logs/` 目錄下生成 JSON 格式的詳細報告，文件名格式：
```
deployment_check_{時間戳}.json
```

報告包含：
- DNS 解析結果
- 所有 URL 檢查結果
- UI 設備通知結果
- 檢查摘要

### 日誌文件

如果使用批處理腳本執行，會在 `logs/` 目錄下生成日誌文件：
```
hourly_check_{日期}_{時間}.log
```

## 任務管理

### 查看定時任務狀態

```powershell
Get-ScheduledTask -TaskName "WuchangHourlyDeploymentCheck"
Get-ScheduledTask -TaskName "WuchangHourlyDeploymentCheck" | Get-ScheduledTaskInfo
```

### 手動觸發執行

```powershell
Start-ScheduledTask -TaskName "WuchangHourlyDeploymentCheck"
```

### 停止任務

```powershell
Stop-ScheduledTask -TaskName "WuchangHourlyDeploymentCheck"
```

### 刪除任務

```powershell
Unregister-ScheduledTask -TaskName "WuchangHourlyDeploymentCheck" -Confirm:$false
```

### 查看任務執行歷史

```powershell
Get-WinEvent -LogName Microsoft-Windows-TaskScheduler/Operational | Where-Object {$_.Message -like '*WuchangHourlyDeploymentCheck*'}
```

## 故障排除

### 問題：DNS 解析失敗

**可能原因**：
- 網絡連接問題
- DNS 服務器配置問題
- 網域配置錯誤

**解決方法**：
1. 檢查網絡連接
2. 使用 `nslookup wuchang.life` 測試 DNS 解析
3. 檢查 DNS 服務器設置

### 問題：URL 無法訪問

**可能原因**：
- 服務器未運行
- 防火牆阻擋
- SSL 證書問題
- 反向代理配置錯誤

**解決方法**：
1. 檢查服務器狀態（Docker 容器、服務進程）
2. 檢查防火牆規則
3. 檢查 SSL 證書是否有效
4. 檢查 Caddy 配置

### 問題：UI 設備不在線

**說明**：
- **這不是問題！** 即使 UI 設備不在線，檢查仍然會正常完成
- 系統會為所有 UI 設備（包括離線設備）創建通知文件
- 通知文件保存在 `notifications/` 目錄，格式：`deployment_check_{IP地址}_{時間戳}.json`
- 當設備上線後，可以自動讀取這些文件獲取最新的檢查結果

**如果設備長期不在線**：
1. 檢查設備電源和網絡連接
2. 確認設備 IP 地址是否正確
3. 檢查防火牆設置
4. 通知文件會一直保存，直到設備上線後讀取

**手動通知設備（當設備上線後）**：
1. 檢查 `notifications/` 目錄中的最新通知文件
2. 將通知文件複製到設備的共享目錄
3. 或通過其他方式（如 SSH、HTTP）手動發送通知

### 問題：定時任務不執行

**可能原因**：
- 任務未正確創建
- Python 路徑錯誤
- 權限問題

**解決方法**：
1. 檢查任務是否存在：`Get-ScheduledTask -TaskName "WuchangHourlyDeploymentCheck"`
2. 檢查任務操作中的 Python 路徑是否正確
3. 檢查任務是否以正確的用戶權限運行
4. 查看任務執行歷史以了解錯誤信息

## 修改檢查頻率

如果需要修改檢查頻率（例如改為每 30 分鐘），可以：

1. **使用 PowerShell 修改現有任務**：

```powershell
$task = Get-ScheduledTask -TaskName "WuchangHourlyDeploymentCheck"
$trigger = $task.Triggers[0]
$trigger.Repetition.Interval = "PT30M"  # 30 分鐘
$task.Triggers[0] = $trigger
Set-ScheduledTask -TaskName "WuchangHourlyDeploymentCheck" -Trigger $trigger
```

2. **重新運行設置腳本**：

```powershell
.\setup_hourly_check_task.ps1
# 選擇選項 1 刪除並重新創建，或選項 2 更新
```

## 注意事項

1. **首次執行延遲**：定時任務會在設置後 60 分鐘首次執行，之後每小時執行一次
2. **SSL 證書**：腳本會嘗試 HTTPS，如果失敗會自動降級到 HTTP
3. **網絡要求**：檢查需要網絡連接，任務設置中已啟用「僅在網絡可用時運行」
4. **UI 設備不在線**：即使 UI 設備不在線，檢查仍然會正常完成：
   - 系統會為所有 UI 設備（包括離線設備）創建通知文件
   - 通知文件保存在 `notifications/` 目錄
   - 當設備上線後，可以讀取這些文件獲取最新的檢查結果
   - 檢查報告仍會正常生成並保存
5. **日誌保留**：建議定期清理 `logs/` 目錄中的舊日誌文件
6. **通知文件**：`notifications/` 目錄中的通知文件會持續累積，建議定期清理
