# 自動問題檢測和修復功能說明

## 概述

系統會自動檢測問題並嘗試修復，無需人工干預。所有修復操作都會記錄在檢查報告中。

**合規要求**：符合 Google 非營利組織合規要求

## 自動修復功能

### 1. Caddy 容器未運行問題

**檢測條件**：
- Caddy 容器未在運行

**修復方法**：
1. 嘗試使用 `docker-compose up -d caddy` 啟動
2. 嘗試使用 `docker start caddy` 啟動
3. 檢查容器是否存在並啟動

**修復驗證**：
- 修復後等待 5 秒
- 重新檢查容器運行狀態

### 2. 首頁不可訪問問題

**檢測條件**：
- `https://wuchang.life/` 無法訪問
- HTTP 狀態碼為 5xx 或連接失敗

**修復方法**：
1. 重啟 Caddy 容器
2. 如果仍不可訪問，重啟 wuchang-web 容器
3. 每次修復後等待 10 秒並驗證

**修復驗證**：
- 修復後等待 10 秒
- 重新檢查首頁可訪問性

### 3. SSL 證書無效或即將過期問題

**檢測條件**：
- SSL 證書無效
- 證書將在 7 天內過期（緊急）
- 證書將在 30 天內過期（警告）

**修復方法**：
1. 重載 Caddy 配置以觸發證書檢查和更新
2. 如果重載失敗，重啟 Caddy 容器
3. Caddy 會自動向 Let's Encrypt 申請新證書

**修復驗證**：
- Caddy 配置重載成功
- 或容器重啟成功（證書會在下次訪問時自動更新）

### 4. DNS 不合規問題

**檢測條件**：
- DNS 記錄不符合 Google 非營利組織合規要求
- A 記錄缺失或錯誤
- MX 記錄未指向 Google 郵件服務
- TXT 記錄缺失（SPF、DMARC、DKIM）

**處理方式**：
- ⚠️ **無法自動修復**：DNS 記錄需要手動配置
- 💡 **記錄問題**：記錄詳細問題到報告中
- 💡 **提示**：建議聯繫 DNS 管理員進行修復

### 5. Caddy 配置文件缺失問題

**檢測條件**：
- `wuchang_os/Caddyfile` 不存在

**處理方式**：
- ⚠️ **無法自動修復**：配置文件需要手動創建
- 💡 **記錄問題**：記錄問題到報告中
- 💡 **提示**：需要手動檢查配置文件

## 修復流程

### 修復步驟

1. **問題檢測**：檢查各項指標，發現問題
2. **問題分類**：根據問題類型選擇修復方法
3. **嘗試修復**：執行修復操作
4. **修復驗證**：等待服務穩定後重新檢查
5. **記錄結果**：記錄修復操作和結果到報告

### 修復優先級

1. **緊急（Critical）**：首頁不可訪問
2. **高（High）**：Caddy 容器未運行、SSL 證書無效
3. **中（Medium）**：SSL 證書即將過期、DNS 不合規
4. **低（Low）**：配置文件缺失（需要手動處理）

### 修復結果說明

- **issues_detected**：檢測到的所有問題列表
- **repairs_attempted**：嘗試修復的操作記錄
- **repairs_successful**：成功修復的問題列表
- **repairs_failed**：修復失敗的問題列表
- **summary**：修復統計摘要

## 注意事項

### 1. 自動修復限制

以下問題**無法自動修復**，需要手動處理：
- DNS 記錄配置（需要 DNS 管理員操作）
- Caddy 配置文件缺失（需要手動創建）
- 網絡連接問題（需要檢查網絡設置）
- 系統資源不足（需要增加資源）

### 2. 修復驗證時間

- **容器啟動**：等待 5-10 秒後驗證
- **服務重啟**：等待 10 秒後驗證
- **證書更新**：需要更長時間（Let's Encrypt 可能需要幾分鐘）

### 3. 修復失敗處理

如果自動修復失敗：
- 問題會記錄到報告中
- 報告會標記為「需要手動處理」
- 下次檢查時會再次嘗試修復

### 4. 修復日誌

所有修復操作都會記錄在：
- 檢查報告：`logs/compliance_cert_check_{時間戳}.json`
- 標準輸出：終端/控制台輸出
- 定時任務日誌：Windows 任務計劃程序日誌

## 最佳實踐

### 1. 定期檢查報告

建議定期查看檢查報告，了解：
- 檢測到的問題
- 自動修復的結果
- 需要手動處理的問題

### 2. 監控修復失敗

如果某些問題反覆修復失敗：
- 檢查系統資源
- 檢查網絡連接
- 檢查 Docker 和容器狀態
- 查看詳細日誌

### 3. 手動處理優先級

根據問題嚴重性決定處理優先級：
1. **緊急**：首頁不可訪問 → 立即處理
2. **高**：Caddy 容器未運行 → 儘快處理
3. **中**：證書即將過期 → 計劃處理
4. **低**：DNS 警告 → 可延後處理

## 故障排除

### 問題：修復失敗

**可能原因**：
- Docker 未運行
- 容器配置錯誤
- 網絡連接問題
- 權限不足

**解決方法**：
1. 檢查 Docker 服務狀態
2. 檢查容器配置
3. 檢查網絡連接
4. 檢查腳本執行權限

### 問題：修復後問題仍然存在

**可能原因**：
- 修復驗證時間不足
- 根本原因未解決
- 服務需要更長時間啟動

**解決方法**：
1. 等待更長時間後手動驗證
2. 檢查服務日誌
3. 手動重啟服務
4. 查看詳細錯誤信息

### 問題：自動修復觸發過於頻繁

**可能原因**：
- 服務不穩定
- 配置問題
- 資源不足

**解決方法**：
1. 檢查服務穩定性
2. 檢查配置是否正確
3. 增加系統資源
4. 調整檢查頻率
