# UI 設備不在線時的處理說明

## 📋 概述

當執行每小時系統部署檢查時，如果 UI 設備不在線，**檢查仍然會正常完成**。系統會為所有 UI 設備（包括離線設備）創建通知文件，等待設備上線後讀取。

## ✅ 正常行為

### 檢查完成

即使所有 UI 設備都不在線，系統仍會：
1. ✅ 完成 DNS 解析檢查
2. ✅ 完成首頁可訪問性檢查
3. ✅ 完成登入頁可訪問性檢查
4. ✅ 生成詳細檢查報告（保存在 `logs/` 目錄）
5. ✅ 為所有 UI 設備創建通知文件（保存在 `notifications/` 目錄）

### 通知文件創建

系統會為以下設備創建通知文件：

- **LUNGsMSI** (192.168.50.84)
- **POS-PC** (192.168.50.88)

**通知文件格式**：
```
notifications/deployment_check_192_168_50_84_{時間戳}.json
notifications/deployment_check_192_168_50_88_{時間戳}.json
```

**文件內容**：
- 檢查時間戳
- DNS 解析結果
- 首頁和登入頁檢查結果
- 檢查摘要
- 目標設備信息

## 💡 設備上線後的處理

### 自動讀取（推薦）

如果 UI 設備配置了自動讀取通知文件的機制：
1. 設備上線後，會自動檢查 `notifications/` 目錄（通過共享目錄或文件同步）
2. 讀取最新的通知文件（按時間戳排序）
3. 顯示檢查結果

### 手動通知

如果設備需要手動通知：

#### 方法 1：通過共享目錄

1. 找到最新的通知文件：
   ```
   notifications/deployment_check_192_168_50_84_最新時間戳.json
   ```

2. 將文件複製到設備的共享目錄

3. 設備讀取文件並顯示結果

#### 方法 2：通過 HTTP（當設備上線後）

如果設備上線並運行 Web 服務，可以手動發送通知：

```bash
python scripts/hourly_deployment_check.py
# 腳本會自動檢測設備是否在線，如果在線則發送 HTTP 通知
```

#### 方法 3：通過 SSH

如果設備支持 SSH，可以：

```bash
# 複製通知文件到設備
scp notifications/deployment_check_192_168_50_84_*.json user@192.168.50.84:/path/to/notifications/

# 或直接在設備上執行腳本查看結果
ssh user@192.168.50.84 "python /path/to/check_script.py"
```

## 🔧 故障排除

### 問題：檢查失敗（不是 UI 設備不在線的問題）

如果檢查本身失敗（DNS 解析失敗、URL 無法訪問），這才是問題：

1. **DNS 解析失敗**：
   - 檢查網絡連接
   - 使用 `nslookup wuchang.life` 測試 DNS
   - 檢查 DNS 服務器設置

2. **URL 無法訪問**：
   - 檢查服務器是否運行
   - 檢查防火牆設置
   - 檢查 SSL 證書是否有效
   - 檢查反向代理配置

### 問題：通知文件沒有創建

1. 檢查 `notifications/` 目錄是否存在且有寫入權限
2. 查看檢查報告中的錯誤信息
3. 確認腳本執行時沒有權限問題

### 問題：設備上線後無法讀取通知文件

1. 確認通知文件路徑正確
2. 檢查文件權限
3. 確認設備可以訪問通知文件所在目錄（如果使用共享目錄）
4. 確認文件格式正確（JSON）

## 📝 最佳實踐

1. **定期清理舊通知文件**：
   - 建議保留最近 24-48 小時的通知文件
   - 刪除更早的文件以節省空間

2. **監控設備狀態**：
   - 如果設備長期不在線，檢查設備狀態
   - 確認設備 IP 地址是否正確
   - 檢查網絡連接

3. **自動通知機制**：
   - 配置設備自動讀取通知文件
   - 設置文件同步服務（如 OneDrive、Dropbox）
   - 使用網絡共享目錄

4. **檢查報告歸檔**：
   - 定期歸檔檢查報告到長期存儲
   - 分析歷史檢查結果找出問題模式
